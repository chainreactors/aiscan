# Habit：一个 System One 系统

> 本文设计的是一个**独立系统**，不是 harness 的一个功能。Jev 是它底层判别引擎的一种实现，不是它的抽象。
> 指纹侧的断言在 [judge](../judge/README.md)，与本文的关系见 §10。
> 面向外部读者的图文版：[habit-design.html](habit-design.html)。

## 结论

传统 harness 是一个**没有 System One 的 System 2**：所有判断要么由 L2 做，要么根本没在做——被正则、阈值和字符串相等顶替。

System One 不是加的一层，是**被编译的判断**：L2 在工作中反复做的那些判断，重复到形状已知，于是可以脱离 L2 运行。

结果是一个**单调下降**的成本曲线：

> 每一轮都在产生原料，每一次编译都在减少工作。
> **同一个 harness 跑得越久，每轮越便宜。**

传统 harness 的每轮成本持平甚至随上下文变长而上升；这个是越跑越快的。

**三个概念、三个调用、一条规则、零个运行期参数。**

## 1. 不可约前提

| | 前提 | 性质 |
|---|---|---|
| P1 | 推理是序列到序列的函数；一轮里模型知道的一切都在序列里 | 机制 |
| P2 | 输出自回归（串行、最贵、无缓存）；输入按前缀匹配 | 机制 |
| P3 | thinking 是生成出来的 token，按 output 计价，且默认留在前缀里 | 机制 + 当前 API 行为 |
| P4 | 存在一种便宜的类型化判断，但它的概率**没有在你的分布上校准** | **产品事实，不是机制** |

由 P4 的性质得一条铁律：

> **任何依赖 P4 数值的设计，必须带一个测量，不能带一个常数。**

### L1 / L2 按能力定义

| | 能做什么 | 代价 |
|---|---|---|
| **L2** | 产生**新的**符号序列 | 慢、贵、输出留在前缀里 |
| **L1** | 从**事先给定的**有限集合里选一个 | 快、约等于免费、不产生 token |

只有这一条差别。四个推论全是强制的：

1. L1 不能给自己出题 ⟹ **题只能由 L2 写**
2. 同一道判断两边都能答 ⟹ **一致率是免费的**
3. L1 不产生 output token ⟹ 短路省掉的正好是 L2 的输出
4. L1 不能解释 ⟹ **审计靠记录，不靠理由**

推论 1 是这套能自转的原因：**编译器就是 L2 自己。**

## 2. 推导

**第一步（P1 + P3）。** L2 生成的 token 分两类：**新工作**，和**重新做已经做过的判断**。后者是纯开销。

**第二步（P2 + P3）。** 重复判断付两次钱：生成时按 output 付（最贵一档、无缓存），之后留在前缀里，每一轮再付一次。

**第三步。** 重复，所以形状已知；形状已知，所以可类型化。

> **重复性本身就是可编译性的判据。** 不需要第二个筛子。

反面同样成立：**新工作天然不可类型化，因为你事先不知道它的形状。** 所以"会不会把 L2 的推理掏空"这个担心自动消解——能被编译的恰好只有开销。

**第四步：结果有两种作用形式。**

判据不是"哪种好"，而是：**这条判断的后果，能不能作用在材料上。**

| | 塑形（旁路） | 注入（写进 prompt） |
|---|---|---|
| 条件 | 后果能作用在材料上 | 不能 |
| 例 | 哪几段相关、是不是重复、命令危不危险、effort 多深 | **我试过这个动作吗**、**目标还差哪几项** |
| L2 | **无感** | 有感 |
| 位置 | 观测入上下文**之前** | 组装 request 时追加 |
| 失败长什么样 | 一次糟糕的检索，漏了东西 | 一条假陈述，L2 会盲信 |
| 额外纪律 | 无。不塑形 = 原样通过，物理事实 | **弃权必须显式出现**——沉默会被读成否定 |

塑形那一类，人不会先看到原始光子、再收到一张纸条说"视觉系统认为这是一张脸"，**你就是看到一张脸**。

但**不能作用在材料上的那一类，如果不注入，L2 还是会自己想一遍**——那这条判断根本没省下来。两种形式都要，按上表分流。

**第五步（P4）。** 概率没校准，就要测。对照物是现成的：**L2 自己声明过的答案**。免费、在你的分布上、每次运行都产出。

> **替换和测量是同一个操作。**

## 3. 三个概念

```go
// Claim：L2 在工作中声明的一次判断。全是自然语言——L2 写得出，L1 吃不下。
type Claim struct {
    Question   string   // 判的是哪一类问题（必要的抽象）
    Background string   // 看着什么判的（背景）
    Chose      string   // 判成了什么（标注）
}

// Reflex：答案空间封闭了的题。L1 唯一吃得下的东西。
type Reflex struct {
    Statement string
    Options   []Option  // 有序；必含"判不了"
}

Compile([]Claim) → Reflex   // 开 → 闭。由 L2 做，因为 L1 只会选不会写
```

**核心是一句话：**

> L1 只会从给定的集合里选。L2 做的判断没有集合。**Compile 就是把集合封闭起来。**

整套设计的其余部分全是它的推论：

| 设计决定 | 从哪来 |
|---|---|
| 封闭必须由 L2 做 | 只有 L2 会写 |
| 需要攒很多条才能封闭 | **一条说不出集合** |
| 每个集合必须含「判不了」 | 封闭 = 宣称穷尽。你宣称不了，得留个出口 |
| 线格式只能用 `choice` | 另两种（`noul` 裸概率、`score` 有序标尺）**都放不下那个出口** |
| 没有阈值、没有置信度、没有分布 | 封闭集合上选一个，不需要任何数 |
| 失败退回原样 | 没封闭的判断**还在 L2 那儿**——它本来就在那儿 |

分成两个类型而不是一个类型加标志位，就为一件事：**没封闭的东西在类型上递不给 L1。**

## 4. 用户心智

`Claim` / `Reflex` / `Compile` 是**理解这套东西的概念，不是使用它的接口**。用户的全部：

```go
h  := habit.New(l1, habit.Can("keep", "drop"))  // 判别引擎 + 我这个 harness 会干的事
l2  = h.Wrap(l2)                                 // 换客户端；生产侧从此隐形
...
for id, act := range h.Sense(obs) { ... }        // 入口处问一次
```

**三个调用，零个需要用户定义的类型。**

### 为什么是这三个

| | 解决的问题 | 没有它 |
|---|---|---|
| `Can(...)` | **选项集不能凭空造。** Compile 只能把判断映射到你已经声明能做的动作上 | 用户写不出 `switch`，因为选项是系统发明的 |
| `Wrap` | **你不知道 L2 在反复判断什么。** 要让它声明，得有人往提示词里加指令；那个人只能是 habit，所以它已经在调用路径上了，顺手收走响应即可 | 仍然能跑，但只能手写 Reflex，**不会自己长** |
| `Sense` | **判断需要一个作用点**，且必须抢在观测写进历史之前 | 编译出来的东西无处可用，**完全不工作** |

`Can(...)` 顺带给了一条安全性质：**系统永远不会做你没列过的事**——「未答即原样」在动作层的具体形式。

两个端口的必要性**不对称**，这决定了上线顺序：

- `Sense` 解决**接入**，必需。
- `Wrap` 解决**自动发现**，是让它自己长的那一半。

所以可以**先只上 `Sense` + 手写 Reflex**：价值确定（省 output token、省轮次），不赌任何东西。`Wrap` 是第二步。`fingers/judge` 今天做的正是第一行。

## 5. 一个 turn 里的位置

```
工具返回 ──→ ① 塑形（观测入上下文之前）
                    │
             组装 request ──→ ② 注入 role:"system"
                    │
                发给 L2 ──→ 响应 ──→ ③ 收走声明（Wrap 做）
                                          │
                                       工具调用 ──→ 下一轮
```

①② 合并成**每轮一次批量 Jev 调用**（Jev 一次可并行问很多题，实测 p50 约 236–276 ms）。每轮增加一次往返、约 $0.002，换掉的是 L2 的 output token——最贵且无缓存的那一档。

## 6. 两个环

```
      ┌──────────── 内环 · 每一轮 ────────────┐
      │                                        │
  观测 ─→ ①②Jev 一次 ─→ 上下文 ─→ L2 ─→ 工具 ─┘
                ▲                    │
         Reflex │                    │ Claim（③，内环的副产品）
                │                    ▼
      ┌──── 外环 · 偶尔，离线 ─────────────────┐
      │  Claim 日志 ─→ Compile ─→ Reflex 集合  │
      └────────────────────────────────────────┘
```

**把外环拆掉，内环就是今天的 harness——一字不差。** 所以启用它不需要赌：Reflex 集合为空时，行为和不装这个系统完全一致。

闭环靠**缺席**闭上：编译成功 ⟹ 判断不再出现在 L2 面前（塑形类）或已被告知（注入类）⟹ L2 不再声明它 ⟹ 生产侧自动停止。退役则反向自动恢复。**没有开关，没有恢复逻辑。**

## 7. 自转：两个解出来的数

一旦出现"一致率到 0.95 就启用"这种人挑的数，就不自转了。

但 L2 是随机函数（P1）——**它和自己也不完全一致**。同一情境重放两次，结论会变。这个自洽率免费可测，且是唯一诚实的标尺：

> **启用**：L1 在历史声明上与 L2 的一致率 ≥ L2 与自己的重放一致率
> **退役**：持续抽样，上式不再成立

你没有理由要求替代品比被替代品更稳。参照物始终是日志里 L2 自己写下的 `Chose`。

**采样从不停。** 启用只是把双跑率从 1 降到 ε，不是切换模式。因为一直在测，测量不会过期，所以不需要时间戳、不需要"训练完成"标志。

**没有置信度阈值。** 弃权已经是一个选项，而阈值那套建在一个**在 0.3–0.8 中段最不可靠**的数上（§11）。两套机制做同一件事，砍掉弱的那套。

## 8. 一条规则

> **未答即原样。** 没有 Reflex、或弃权——`Sense` 返回空，调用方什么都不做，行为和没有这个系统时逐字节相同。

塑形侧这是**物理事实**（不塑形就是原样通过）；注入侧需要一条纪律配合：**弃权必须显式写进注入内容**，不能沉默——因为 L2 会把沉默读成否定，而它信被告知的事实胜过信自己读出来的。

## 9. 设施

以下全部是设施，不是抽象。换掉它们，§3 的三个概念一个都不动。

**判别引擎。** L1 的实现。`ID()` 标识端点和模型——**它一变，所有 Reflex 的验证作废**。候选：Jev（托管）、Laya（421M，Apache-2.0，本机，含多语种变体）、Kev（实现同一 `/v1/systemone` 契约）。

**只增。** 缓存按前缀匹配；编辑过的历史现在还可能直接 400（preserved thinking 的 history-editing check，2026-08-31 之后创建的账号）。塑形天然满足（在入上下文之前）。

**注入信道是已解决的问题**，不需要自己设计：

| 需求 | 实现 | 可用性 |
|---|---|---|
| 追加一条 operator 事实 | `{"role":"system","content":"..."}` 追加进 `messages[]`，**不触发 messages 缓存失效** | Opus 5 / 4.8 / Fable 5 / 5.1 / Mythos，**今天就有，无需 beta header**；Sonnet 5 不支持，按 400 兜底 |
| 只在这一轮生效 | 同上 + `clear_at:"next_user_message"`：渲染一轮后留在 transcript 里但清空，**不计输入 token、仍在前缀里** | beta `mid-conversation-system-clear-at-2026-08-21` |
| 按轮调 effort | `{"role":"system","content":[],"output_config":{"effort":...}}` | beta `mid-conversation-output-config-2026-07-01`，Opus 5 / Fable 5.1 |

官方明示 `role:"system"` 是**不可伪造的 operator 信道**（user turn 里的文本可被任何写进输入的东西伪造）。对本仓库是决定性的：`judge` 的 state 是被扫描目标返回的响应，敌手可控。

**模型不能换。** 缓存按模型隔离，无逃生口。effort 可以（上表第三行）。

**经济学。** thinking 按 output 计价且留在前缀（P3），所以短路省两样：生成时的 output token（最贵一档、无缓存）+ 此后每轮的前缀增长。参考量级：Opus 5 $5/$25 每 MTok，Sonnet 5 $2/$10；缓存读约 0.1×，写 1.25×（5 分钟）/ 2×（1 小时）；Jev $0.042/M，输出免费。

## 10. 边界：短路 ≠ 新权威

§1–§9 整套只对一种东西成立：

| | 短路（塑形或注入） | 新权威 |
|---|---|---|
| 做什么 | 替换掉**已经在发生**的判断 | 做一件**原本没人在做**的判断 |
| 有对照物吗 | 有——L2 的声明 | 没有 |
| 怎么定阈值 | 噪声底判据，免费 | 真标注，要花钱 |
| 失败时 | 退回原状 | 产生一个原本不存在的后果 |

**`judge` 的 `presence` 是第二种。** 规则引擎命中之后，原本没有任何东西在判"这个产品是不是真的在跑"。两个后果：

1. `judge.New` 默认的 `MinConfidence = jev.DefaultMinConfidence`（0.3）没有依据，**也不可能通过一致率取得依据**——没有"原来的做法"可比。而 0.3 恰好落在 Jev confidence 最不可靠的 0.3–0.8 中段下沿。
2. `presence.go` 里 `Refuted → Rejected` 删掉了规则引擎的命中，**弃权或出错不退回原样，而是丢召回**——直接违反 §8。指纹场景里召回损失是静默的。

两条路都行：改成退回（`Rejected` 降级为"标记待审"），或者承认它是新权威、用真标注给它有依据的阈值。真标注已在仓库里：`.judge-data/product-authenticity/` 的 17 份带标签部署响应，SHA256 已固定。

## 11. 已知未解决与风险

1. **Projection —— 最弱的工程点，但有了方向。** 每条 Reflex 喂哪段 state：64K 总 / 32K 单问上限、每页 40 条、8 个产品版本。两个来源现在都有了：`Claim.Background`（L2 自己说它看了什么），以及**每轮先用一条元反射选出这轮适用的子集**（选项就是反射集合本身——同一个机制作用在自己身上）。**但这是扩展性机制，不是第一版**：反射少时一次批量问掉即可，撞上上限才需要。
2. **抓不到系统性偏差。** 判据只保证"不比 L2 更差"，不保证对。两边可以一致地错，而一致的错看起来像确证。
3. **标定不可移植。** 独立测评：公开 benchmark ECE 0.024–0.032，自建分布 0.107（噪声底 0.024）；一篇 pentest 论文在自有评估集上测得 Jev ECE 0.246。confidence **两端可靠、0.3–0.8 中段最不可靠**。这是 §7 砍掉阈值的经验依据。
4. **注入比塑形危险。** L2 信被告知的事实胜过信自己读出来的。所以注入侧必须带 §8 那条纪律，而塑形侧不需要。能塑形的就不要注入。
5. **无内省。** L1 不给理由，审计只能靠记录（题、证据摘要、选项、动作）。
6. **CJK 精度。** 本仓库目标大量是中文 web 资产，需专门留中文样本。
7. **端到端证据很薄。** 唯一的整机对照来自一篇 pentest harness 论文（单次运行，作者自陈不具统计效力）：墙钟 32m12s → 26m53s，findings 16 → 18，**但场景命中 10/13 → 9/13**。支持省墙钟，**不支持"完成率不降"**。
8. **早期访问。** 无论文、无开放权重、payload 形状可能变。生产必须钉版本，不用 `jev-latest`。

## 12. 术语

**启用**：`habit`（系统）、`Claim`（开）、`Reflex`（闭）、`Compile`（封闭集合）、`Can` / `Wrap` / `Sense`（用户的三个调用）。

**退役**：`Verdict`、`Is`/`Pick`/`IsMany`/`IsAll`、`Brief`（含 A1/A2 双写）、`Groove`、`Startle`、`Precedent`、`Impression`、`Floor`、`MeasuredAt`、`Declare`（塌进 `Wrap`）、`Distribution`（运行期不需要数）。

**从未启用**：Sieve、Assay、Attest、Ledger、Rung、SiftAct、Understudy、Harvest、CoDE。

**只用 `choice`**：因为只有它放得下强制的「判不了」（§3）。`noul` 返回裸概率、`score` 是一条标尺，两者都没有弃权位；要给它们造一个，只能对概率设阈值，而那是自由参数。

**已知坑**：`instructions` 与 `criteria` 自相矛盾会明显拉低质量。Compile 阶段的不一致样本最容易暴露这类规约错误。

**与本仓库现状的差异**：

### 2026-09-27 v5 —— 注入回来了，用户心智收窄到三个调用

**更正**：v4 §2 第四步写的是「旁路，不是注入」。**那一条越界了。** 注入的风险（L2 会盲信一条陈述）是真的，但据此把注入整个否掉，等于把"我试过这个动作吗""目标还差哪几项"这一整类判断划出系统——而它们如果不注入，L2 还是会自己想一遍，这条判断根本没省下来。

正确的判据是**后果能不能作用在材料上**：能 → 塑形；不能 → 注入。两种都要。

连带更正：v4 反对注入有一半理由是"要设计注入信道、会破坏缓存"。这条不成立——`role:"system"` 追加、`clear_at:"next_user_message"`、per-message effort 三个原生机制都在，且**都不触发 messages 缓存失效**，还附带不可伪造这个对本仓库决定性的性质。我把一个已解决的问题当成了论据。

**加法**：

1. **越跑越快**（结论）——成本单调下降是这套东西的头条，v4 埋得太深。
2. **§4 用户心智**——`Claim`/`Reflex`/`Compile` 降级为理解用的概念，接口收窄成 `New(l1, Can(...))` / `Wrap(l2)` / `Sense(obs)`。`Declare` 塌进 `Wrap`（habit 必须控制提示词，所以它已经在调用路径上）。
3. **`Can(...)`**——选项集不能凭空造，只能映射到调用方声明过的动作上。顺带得到"系统永远不会做你没列过的事"。
4. **两个端口的必要性不对称**（§4）——`Sense` 必需、`Wrap` 是自动发现。由此得出上线顺序：先 `Sense` + 手写 Reflex，再 `Wrap`。
5. **§5 一个 turn 里的位置**——①塑形 ②注入 ③收声明，①②合并成每轮一次批量调用。
6. **元反射**（§11 风险 1）——每轮先选出适用的反射子集，是 projection 的方向；标为扩展性机制而非第一版。
